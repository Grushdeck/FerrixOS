# Устройство Ferrix OS

## Контракт между загрузчиком и ядром

`boot.asm` делает следующее — если пишете свой загрузчик, он должен повторить то же:

1. загрузить `KERNEL.SYS` целиком по адресу `1000:0000` (ядро собрано с `org 0`,
   сегмент может быть любым — оно само ставит `DS=ES=SS=CS`);
2. записать номер загрузочного диска (`DL` из BIOS) по адресу `0000:0500`;
3. оставить в BPB загрузочного сектора (`0000:7C18` — секторов на дорожку,
   `0000:7C1A` — головок) реальную геометрию диска, полученную от BIOS
   (если там нули, ядро использует 18×2);
4. передать управление `jmp 1000:0000`.

`boot.asm` читает параметры тома из собственного BPB (зарезервированные секторы, размер FAT,
число копий, размер корня, общее число секторов), по числу кластеров определяет FAT12/FAT16,
находит `KERNEL.SYS` в корневом каталоге и читает его по цепочке FAT, поэтому файл не обязан
лежать первым и непрерывно. Ядро при старте (`vol_init`) берёт те же параметры из BPB по адресу
`0000:7C00` — загрузочный сектор нельзя затирать до запуска ядра.

Загрузчик молчит, если всё хорошо (сообщения только `No KERNEL.SYS` и `Disk error` — в 512 байт
не уместилось больше), ядро печатает строку `Kernel loaded at 1000:0000. Initializing...`
и выдерживает паузу ~1,5 с, прежде чем очистить экран — так лог виден и на реальном ПК,
где раньше экран очищался мгновенно.

## Карта памяти

| Адрес | Что там |
|-------|---------|
| `0000:0500` | Номер загрузочного диска (кладёт загрузчик) |
| `1000:0000` | Ядро (`KERNEL.SYS`) |
| `1000:FFFE` | Вершина стека ядра (образ ядра > 31 КБ, поэтому стек — в верхней части сегмента) |
| `2000:0000` | Буфер текущего каталога (до 32 секторов = 16 КБ: корень FAT16 на 512 записей) и буфер чтения сектора данных |
| `3400:0000`, `3800:0000`, `3C00:0000` | HD Audio: два буфера 16-бит стерео по 16 КБ и список BDL (область не пересекается с окнами `gui`) |
| ядро, `fat_cache` | Окно FAT — 2 сектора (1 КБ) внутри образа ядра; грязное окно сбрасывается во все копии FAT при смене окна и после каждой операции |
| `3000:0000` | Буфер записи сектора данных |
| `4000:0000` | Сегмент внешних программ `.FAP` (код + данные + стек, 64 КБ) |
| `5000:0000`, `7000:0000`, `8000:0000` | Окна `gui` (по 64 КБ на программу); вне `gui` 5000h — служебный: списки панелей `fm` (0000h/2000h), копия экрана для заставки (8000h), текст скрипта (9000h) |
| `6000:0000`–`9F000` | Буфер `view` (файл до ~250 КБ), `cat`/`type` (до 60 КБ); `cp` работает потоково через буфер каталога |
| `9000:0000`, `9800:0000` | Два DMA-буфера `play` по 32 КБ для SB16 / порция данных для HDA-ресэмплера (внутри области `view`, выше окон `gui` — поэтому `play` из окна плеера не портит соседние программы) |
| `A000:0000` | Видеопамять режима 13h (`view`) |
| `B800:0000` | Видеопамять — весь текстовый вывод идёт напрямую (свой телетайп с прокруткой, атрибут 0x07; BIOS-телетайп на реальном железе «подхватывал» зелёный цвет промпта) |

## Раскладка тома

Ядро поддерживает FAT12 и FAT16 с сектором 512 байт и **1 сектором на кластер**
(так адресуется весь том 16-битным номером кластера без умножений); до 32 МБ (65 520 секторов,
доступ через CHS `int 13h` — геометрию сообщает BIOS). Все параметры берутся из BPB.

| | Дискета 1.44 МБ (FAT12) | Диск 32 МБ (FAT16, `build.sh`) |
|-----|------------|------------|
| 0 | Boot-сектор с BPB | то же |
| FAT1, FAT2 | LBA 1–9, 10–18 | 1–256, 257–512 |
| Корневой каталог | 19–32 (224 записи) | 513–544 (512 записей) |
| Данные | 33–2879, кластер N → LBA N+31 | 545–65519, кластер N → LBA N+543 |
| Кластеров | 2847 (1423 КБ) | 64 975 (32 487 КБ) |

Том без таблицы разделов (как дискета): при записи на флешку образ пишется с нулевого сектора.
Том другого размера форматируйте с `-s 1` (`mkfs.fat -F 16 -s 1 -r 512`), не больше 65 524 кластеров.

Размещение файлов:

```
/KERNEL.SYS            — ядро (должно лежать в корне: его ищет boot-сектор)
/SYSTEM/USER.CFG       — настройки пользователя (мастер первого запуска)
/SYSTEM/AUTOEXEC.SH    — автозапуск (необязательно)
/SYSTEM/FM.CFG         — состояние файлового менеджера
/SYSTEM/SYSAPPS/*.FAP  — стандартный пакет программ (fm, mono, calc, paint, игры)
```

Подкаталоги хранятся цепочкой кластеров (до 32 секторов = 512 записей); при
заполнении ядро само добавляет кластер.

## Известные ограничения

- Длинные имена (LFN) только читаются; создаются файлы с именами 8.3
- `cp` копирует только файлы; каталоги переносите через `mv`
- `view` не поддерживает сжатые (RLE) и 1/4/16-битные BMP, а также PNG/JPG
- Звук: Intel HD Audio или Sound Blaster 16; AC'97 и USB-звук не поддерживаются. HDA-драйвер проверен в QEMU (ICH6) — реальные кодеки могут требовать особых настроек (выбор пина, GPIO)
- `play` — только несжатый 8-битный PCM WAV (16-битные и OGG/MP3 нужно конвертировать `ffmpeg`); нужен Sound Blaster 16 на 220h/DMA 1 (в QEMU — `-device sb16`)
- `write` принимает до 1022 байт (длина командной строки) — для большего есть `mono` (56 КБ)
- Подкаталог вмещает до 512 записей (32 кластера); том — до 32 МБ, кластер = 1 сектор (файлы > 64 КБ при открытии перебирают цепочку по 512 байт — для больших файлов это заметно медленнее)
- `gui`: окна подгоняются под размер, который программа задаёт через `FAPI_WM`; не более трёх окон; `view`/`play` и `.SH`-скрипты выполняются на весь экран (их буферы лежат в сегментах окон); заставка при работе `gui` не запускается
- `synth`: нужен 386+ и HD Audio; в окне `gui` он забирает клавиатуру себе (IRQ1) — остальные окна не получают клавиш, пока он открыт
- `.SNG` в `ferramp` играет через перезапуск (`FAPI_EXEC synth -p`): позиция в списке сбрасывается, автопереход на следующий трек после песни не делается
- `ferpy`: только 16-битные целые, строки cp437, нет списков/словарей/вещественных чисел/исключений; один исходный файл; размер программы ограничен лимитами `iron` (16 КБ кода, 800 символов)
